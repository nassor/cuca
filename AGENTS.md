# Repository Guidelines

## Project Overview

CUCA (**Compact Universal Client for Agents**) is a high-performance, asynchronous Rust client library intended to sit between autonomous agent orchestrators and LLM backends: an ultra-low-overhead runtime that monitors, parses, and dispatches multi-modal SSE streams. Tagline: *"Legendary vigilant witch; small footprint that constantly watches for responses."*

Current state: **implemented**. The unified client (`CucaClient`/`CucaClientBuilder`), the zero-allocation SSE parser, eight provider adapters (seven HTTP, one in-process local engine), twelve feature-gated plugins, and seven explicit-call services, including the speculative fast/slow orchestrator, are all implemented. The `server` and `server-tui` features add an application layer, the `cuca` binary: a model server, a balancer and a terminal UI over the local engine.

## Architecture & Data Flow

**Implemented:** the unified client pipeline, the SSE parser, the provider adapters, the plugins, and the services. The architecture:

- **Unified provider abstraction**: one `UnifiedRequest` in, one normalized `AgentResponseStream` out, across OpenAI, Anthropic, DeepSeek, Gemini, llama.cpp, vLLM, LM Studio and the in-process local engine (`ProviderEndpoint`, `UnifiedMessage`, `MessageContentBlock`). Every adapter maps the request's `temperature`, `max_tokens`, `top_p`, `top_k`, `seed` and `stop` (the shared part is `provider::insert_sampling`). A backend without an equivalent rejects the request with `CucaError::Config` instead of dropping the value: `top_k` on OpenAI and on DeepSeek's native route, `seed` on Anthropic and on DeepSeek's Anthropic bridge. `provider-local` is described in *Local provider*.
- **Zero-default provider policy**: no provider compiled by default (`default = []`); a `compile_error!` fires if no provider feature is enabled. Providers are opt-in Cargo features (`provider-openai`, `provider-anthropic`, …).
- **Zero-allocation SSE engine.** `SseStreamParser` is a byte state machine over `bytes::BytesMut`; inbound chunks are scanned with `memchr` in contiguous buffers, with no intermediate string allocation.
- **Plugins and services.** A plugin implements `trait CucaPlugin` (`on_request` / `on_stream_chunk` / `on_response_complete`) and observes the request/stream pipeline; it is compile-time feature-gated and carries its own non-core dependencies. A service is an explicit-call, client-level capability driven by direct method calls instead of pipeline hooks; a service MUST NEVER implement `CucaPlugin`, so registering one with `register_plugin` is a compile error rather than an inert no-op.
- **Fast/slow orchestration** (`service-speculative`): `ModelOrchestrator` + `SwappableModelPair`; complexity routing → speculative draft generation → fallback cascades on malformed output.
- **Server tier**: `server`/`server-tui` build the `cuca` binary over `provider-local` (`serve`, `balance`, `tui`); see *Server*.

Data flow: builder selects provider → `UnifiedRequest` passes through registered plugins (`on_request`) → provider adapter translates to vendor protocol → SSE stream parsed into `MessageContentBlock` events → each chunk passes plugins (`on_stream_chunk`) → `on_response_complete`.

## Local provider

`provider-local` (`src/provider/local/`) runs a language model in the process: pure Rust (candle on the CPU, burn and CubeCL on a GPU), no HTTP endpoint, no FFI, no llama.cpp (a design reference only). It is model-agnostic: `general.architecture` selects a row of one table, and no shared engine path may assume one model. Supported models were released in 2025 or later; code that only an older model needed is deleted, and a newly popular architecture is added through the generic loader.

- **Architectures** (`model/arch.rs`, `Arch::ALL`, 20 entries): `gemma4`, `gemma3`, `llama`, `qwen2`, `qwen3`, `phi3`, `smollm3`, `granite`, `qwen3moe`, `olmoe`, `qwen35` and `qwen35moe` (hybrid delta-net), `olmo2`, `ernie4_5`, `muse-glimmer`, `mistral3`, `mistral4` (multi-head latent attention, fused gate/up experts, ungated shared expert), `deepseek41` (hyper-connection streams, latent attention with a window and compressed sparse attention, Engram lookups, `sqrtsoftplus` MoE; CPU engine in `model/cpu/hyper.rs`, `csa.rs`, `hc.rs`, `kvquant.rs`, `engram.rs`), plus the drafter architectures `gemma4-assistant` and `mistral4-eagle`. `Behavior` flags carry the differences; the loader derives every dimension from the GGUF metadata and tensor shapes. An unknown architecture, tokenizer or `tokenizer.ggml.pre` fails naming the value. The GPU engine (`model/gpu.rs`) runs every model architecture; `deepseek41` goes through `model/gpu/hyper.rs` and the kernels `hc_kernel.rs`, `csa_kernel.rs`, `topk_kernel.rs`, `qdq_kernel.rs` and the MXFP4 formats of `moe_kernel.rs`, on one device (tensor parallelism is rejected, `gpu_layers` only at cuts that keep each cache source with its readers).
- **GGUF** (`gguf/`): the crate owns its reader, because candle's fails on tensor types it does not implement. `GgufType` adds MXFP4 (17 bytes per 32 values: 16 bytes of E2M1 nibbles and an E8M0 scale), IQ4_NL (18 bytes per 32: nibbles through a 16-entry table, f16 scale) and I8 to candle's float, legacy and K-quant types, and keeps an unrecognised id as `Unknown(id)` so a header with it still opens and only that tensor's request fails, naming tensor and type. Versions 1 to 3, `general.alignment` honoured. `model/quant.rs::dequant_row` decodes F32, F16, BF16, Q4_0, Q4_1, Q5_0, Q5_1, Q8_0, IQ4_NL, MXFP4 and I8 in place; K-quants and Q8_1 go through candle's allocating dequantizer. A split set (`split.no`, `split.count`, metadata in part 1) opens as one `Content`; the parts may sit on different volumes.
- **Generic mechanisms**: `Behavior` flags `hyper_connections` (HC residual streams, `model/hc.rs`), `compressed_attention` (compressors, indexer, candidate blocks, kv and index source layers, attention sinks, grouped output projection, `model/csa.rs`, `kvquant.rs`), `engram` (per-layer token embeddings, `model/engram.rs`, `engram_io.rs`) and `moe_ext` (`sqrtsoftplus` router, selection bias, SwiGLU clamps) gate these paths from the GGUF metadata; no shared path tests for `deepseek41` by name, and another architecture that sets a flag gets the mechanism. `deepseek41` sets all four plus `kv_qdq`.
- **Engram**: `per_layer_token_embd` (hashed n-gram rows; token ids go through the compressed token map, multipliers and prime buckets come from `ple.*` metadata) stays in the GGUF and is read by `EngramCache::reader_threads` positional readers (1 to 64, default 16), sorted by file offset, at pass entry and for the next prefill chunk. An LRU of `EngramCache::ram_bytes` (1 MiB to 1 TiB, default 4 GiB; a row counts its file bytes plus `ENTRY_OVERHEAD` 48) holds the rows as the file stores them, allocated in segments as it fills. At the bound the least recently used row is evicted, a row evicted before its pass uses it is read again, and output never changes. `LocalModel::engram_stats` returns `EngramStats`; a model split by `gpu_layers` shares one table. Settable as `LocalModelConfig::engram` or `CUCA_LOCAL_ENGRAM`.
- **Pipeline**: the tokenizer (`tokenizer/`: SentencePiece `llama`, byte-level BPE `gpt2` with hand-written pre-tokenizers per `tokenizer.ggml.pre` including `tekken`, `deepseek-v3` and `joyai-llm` (a three-split chain), and the `gemma4` scheme) and the chat template (`chat/`: the GGUF's Jinja through minijinja) come from the file. `LocalModelConfig::chat_template` or `ModelPreset::template` replaces the template, and the names `mistral-v7`, `mistral-v7-tekken` and `deepseek-v41` expand to builtin Jinja. `ChatFormat` derives the end-of-generation ids, the reasoning markers and the tool-call syntax (`ToolSyntax::Dsml` for DeepSeek-V4.1, parsed by `parse_dsml_calls`); a template that reads `reasoning_budget` thinks unless the request disables it, with `low` for a minimal or low effort and `high` above. `OutputParser` (`output/`) emits `Text`, `Thinking` and `ToolCall` blocks.
- **Sampling** (`sampling.rs`): for each of temperature, `top_k` and `top_p`, the request wins over `SamplingConfig`, which wins over the file's `general.sampling.*` keys, which win over the built-in default. A request `seed` wins over `SamplingConfig::seed`; the request's `stop` strings end a reply before their first occurrence (`engine/stop.rs`).
- **Sources** (`ModelSource`): `HuggingFace` (pinned revision, resumable download, SHA-256, optional split `parts` and pinned `template`), `File`, `Checkpoint { repo, revision }` and `Dir`. A safetensors checkpoint is converted once to a cached GGUF by `convert/`, a pure-Rust port of llama.cpp's `convert_hf_to_gguf.py` (`LocalModelConfig::convert.quant`: `f16`, `q8_0` default, `q4_0`; FP8 weights are dequantized while converting). Split GGUF files (`<base>-00001-of-0000N.gguf`) open natively with `gguf::Content::open_with`: the parts are looked for next to the named file and in `LocalModelConfig::shard_dirs`, a split Hugging Face download keeps its parts in the cache, and nothing is merged or copied. `ModelSource::PRESETS` is `PRESET_TABLE` (25 entries: 23 models and 2 drafters, each pinned to a commit and SHA-256, none for `deepseek41`); the first, `gemma4-e2b-q4_0`, is the default. A string parses as a preset name, `repo:revision:file` or `repo:revision`.
- **DeepSeek-V4.1 conversion** (`convert/deepseek41/`: `plan.rs`, `stream.rs`, `meta.rs`, `hparams.rs`; `convert/engram.rs`): `ModelSource::Checkpoint { repo: "deepseek-ai/DeepSeek-V4.1-Flash-1017", revision }` (FP8 dense, FP4 experts, 510 GB of shards) converts once to a split set next to the nominal `model-<quant>.gguf`: `-00001-of-00003` metadata only, `-00002-` backbone, `-00003-` `per_layer_token_embd` (2 parts without Engram layers), parts 2 and 3 renamed before part 1 so part 1 marks a finished set; the DSpark stages go to `dspark-model-<quant>.gguf`. Matrices follow `quant` (dense FP8 becomes Q8_0 at the default `q8_0`), FP4 experts repack byte-wise to native MXFP4, `quant = f16` dequantizes exactly to F16, hc, router, sink and norm tensors are F32, `conf_proj.weight` is a 1-D vector, the vision tower, aligner and `ffn.gate.bias_vl` are skipped. `ConvertConfig { quant, engram_quant }`, `EngramQuant::{Q8_0 (default), Q4_0, Bf16}` (exported from the crate root); a non-default `engram_quant` adds `-engram-<name>` to the cached file name. Sizes: backbone 297.96 GB, Engram table 208.90 GB at Q8_0 (about 110.6 GB at Q4_0, 393.2 GB at Bf16), drafter 7.91 GB. A free-space check of the output volume (`sysinfo::Disks`; skipped where the platform reports none) fails with `CucaError::Config` before any write. The stream holds two buffers of at most `BLOCK_ELEMS` (32 MiB of f32); measured peak RSS about 220 MB, release build, this checkpoint, default precision, I/O bound (2 h 44 min for the 507 GB set on an HDD-class volume at about 52 MB/s). `convert/engram.rs` ports numpy's `SeedSequence`/`PCG64` hash multipliers and uses `tokenizers` normalizers for the compressed token map. Verified: unit and e2e tests, the gated oracle test against the tiny torch oracle (`CUCA_LOCAL_DS41_REF`; bit-exact tensors and metadata), and a conversion of the real release checkpoint whose header matches ggml-org's published headers (62 of 62 metadata keys, 1003 of 1043 tensor names, identical shapes, only documented dtype differences). The Engram Q8_0 error on the real table is not measured.
- **Devices**: `LocalDevice` is `Cpu` (default), `Vulkan`, `Metal`, `Cuda` or `Rocm`, enabled by `provider-local-gpu` (the shared engine, no backend alone) plus `provider-local-vulkan`, `-metal`, `-cuda` or `-rocm`. Every variant exists in every build: a device whose feature is off fails `LocalModel::load` with `CucaError::Config`, one that cannot be opened with `CucaError::Provider`. There is no automatic selection. On a GPU, Q4_0, Q4_1 and Q8_0 matmul weights stay block-quantized, F32, F16 and BF16 upload as f32, MXFP4 experts stay in the file's format (`ExpertFormat::Mxfp4` in `model/moe_kernel.rs`), and every other quantized dtype (Q5_0, Q5_1, Q8_1, K-quants) is requantized to Q8_0 at load.
- **GPU placement**: `gpu_layers` puts the last `n` layers and the head on the GPU and the first layers and the embeddings on the CPU (`model/split.rs`). `shards` and `LocalModelConfig::set_devices("vulkan:0+vulkan:1")` split a model over several GPUs (`model/tp.rs`; all-reduce through NCCL on CUDA, host-staged in shard order elsewhere); it rejects drafters, tiered and host experts, delta-net layers, latent attention (`mistral4`) and full-width Q/K norms (`olmo2`, `olmoe`) with `tensor parallelism: ...`.
- **Experts**: `ExpertPlacement` is `Resident` (default), `Tiered(ExpertTiers { ram_bytes, device_bytes, loader_threads, warm_from })` (`model/tier.rs`: routed experts stay in the GGUF and load on demand through byte-bounded caches with learned heat; missing experts of a layer that are adjacent in the file, when its gate, up and down tensors store expert after expert, are read as one run of at most 4 per matrix) or `Host { layers }` (GPU only: routed experts stay in RAM and the CPU computes them; not combinable with tiers or shards). Output equals the resident mode's on the same device.
- **K/V and batching**: K/V lives in blocks of 16 positions (`model/paged.rs`) named by token ids, with a prefix store, so `prompt_cache_usage.read_tokens` is a multiple of 16. The step scheduler (`engine/scheduler.rs`) runs up to `BatchingConfig::max_sequences` requests (1 to 64, default 4) in one forward pass per step over one K/V pool (`kv_tokens`, default twice `context_length`, the memory knob), preempts the youngest sequence when the pool is full, and reports through `LocalModel::serving_stats`. On the CPU a sequence's output equals what it produces alone, bit for bit. A compressed group of rows (`deepseek41`) has `stride` tokens per row, so a block spans `16 * stride` tokens and prefix hits are multiples of the largest stride.
- **CPU kernels**: Q4_0, Q4_1, Q5_0, Q5_1, Q8_0 and MXFP4 matmuls, MoE and tiered experts included, run through the batch-invariant row-batched kernel (`model/qmm.rs`); K-quants and every other dtype run on candle's per-row kernel. A dtype MUST NOT dispatch to different kernels by row count: a row's bits must not depend on the batch size. The kernel decodes four weight rows into `i16` lane pairs once and multiply-adds them against every activation tile (`wide`: one `vpmaddwd` and sixteen `f32` lanes per block pair under `-C target-cpu=native`), and quantizes the activations over the pool; its result equals the module docs' scalar definition bit for bit (`the_kernel_equals_the_scalar_definition_bit_for_bit`).
- **Drafters** (`LocalModelConfig::drafter`, `draft_tokens` 1 to 16): `DrafterSource::File` loads the Gemma 4 MTP assistant, the Mistral Small 4 EAGLE head, a DFlash block drafter or the DeepSeek-V4.1 DSpark drafter (`dflash` GGUF with `dflash.hyper_connection.count`, `model/cpu/dspark.rs`: stages of the target's own block kind with window-only attention, blocks of 5 drafted at once from the target's hidden features, a Markov head biasing each row's logits and a confidence head); `InTrunk` uses a head inside the target's own file (Qwen 3.5). The EAGLE, DFlash, DSpark and in-trunk drafters are CPU only; an in-trunk drafter serves one sequence at a time and a file drafter speculates only while one request runs alone. Speculative output equals plain greedy output.

## Server

`server` (`src/server/`, binary `src/bin/cuca.rs`) is an application layer above core and `provider-local`; `server-tui` adds the terminal UI in `src/server/tui/`. It serves `LocalModel`s over an OpenAI-compatible HTTP API (axum), balances several servers, and reports telemetry. Tier rules: it depends on core and `provider-local` only, never on a plugin or a service; no other module names `crate::server`; `server` enables `provider-local`, so it satisfies the provider gate; the library returns `ServerError` (no `anyhow`), and the binary only parses arguments.

- **Model server**: `serve` loads models concurrently (`registry.rs`), answers `/health` 503 until all are ready and exits on a failed load. Chat requests go through `LocalModel::generate` (`LocalGeneration` and `GenerationReport`: exact usage, finish reason, queue seconds), not `CucaClient`, because the client path reports neither the finish reason nor per-request timings and would copy every block. `openai.rs` holds the wire mapping and rejects what the engine cannot honour (`n`, `logprobs`, penalties, `logit_bias`, `response_format`, image parts) with a 400 naming the field; `/v1/completions` is absent because the engine has no raw prompt path. A client disconnect drops the stream task, which drops the `LocalGeneration` and cancels the engine request.
- **Telemetry**: `metrics.rs` renders Prometheus text by hand over fixed atomics and histograms; `latency.rs` is the sliding window of finished requests; `collector.rs` samples each model's `ServingStats` and the machine every second into 300-entry rings and builds the `StatsSnapshot` (`stats.rs`, the serde wire types shared with the balancer and the TUI, `#[serde(default)]`, fields added and never renamed); `diagnosis.rs` is a table of data-driven rules with `Thresholds`; `sysmon/` is the system sampler (sysinfo, NVML, WMI on Windows, sysfs on Linux, ioreg on macOS).
- **Balancer** (`balancer/`): `routing.rs` (pure: candidates, load score, rendezvous hashing, the fallback rule `score > 2 * min + 2`), `upstream.rs` (pollers, health, ejection, backoff), `proxy.rs` (routes, streaming passthrough, at most 2 retries on a connect error or a 503 before any body byte), `snapshot.rs` and `diagnosis.rs` (the balancer's stats view and its causes), `metrics.rs`. A proxied response with a declared `content-length` finishes its tracker by counting bytes, because hyper does not poll past it.
- **TUI** (`tui/`): follows `/cuca/v1/stats/stream` on a tokio task and draws on a blocking thread; tests draw it on `TestBackend`.

## Code Conventions & Common Patterns

Follow Rust defaults plus the conventions below:

- **Naming**: snake_case functions/variables, CamelCase types (`CucaClient`, `CucaPlugin`, `UnifiedRequest`, `MessageContentBlock`); plugin names are `&'static str` (e.g. `"opentelemetry-observability"`).
- **Error handling**: `CucaError` + `PluginError`; plugins return `Result<(), PluginError>`, client methods `Result<AgentResponseStream, CucaError>`. Avoid `unwrap`/`panic` in library code.
- **Async:** provider and async plugins use Tokio; the public stream contract is `futures_core::Stream` and yields `Result<MessageContentBlock, CucaError>`.
- **Feature gating:** `default = []`; `lib.rs` requires at least one `provider-*` feature. Provider, plugin, and service code MUST be `#[cfg(feature = "…")]`-gated, and each non-core dependency MUST be enabled only by its owning feature via `dep:`. Cross-tier feature and code edges additionally obey *Plugins and services* below.
- **Dependency injection**: providers via builder (`CucaClient::builder().with_provider(…).register_plugin(Arc<dyn CucaPlugin>)`); plugins as `Arc<dyn CucaPlugin>` (Send + Sync).
- **State management**: session state is append-only trajectory logs with fork support (`SessionStorePlugin`); no global mutable state.
- **Memory**: state that grows with traffic is capped, evicting or offloading at the bound; see *Memory discipline* below.
- **Data modeling**: `#[derive(Debug, Clone, serde::Serialize, serde::Deserialize)]` on all wire types.

### Plugins and services (no cycles)

Core, plugins and services form a DAG at three levels: Cargo features, `#[cfg]`/import edges, and runtime coupling. Cargo rejects feature cycles; the code and runtime levels are on contributors.

**Tiers.** Core (`types`, `request`, `error`, `sse`, `session`, `plugin`, `client`, `provider`, `export`, `canonical`, `tokenize`, `cost_otel`) sits below every plugin and every service. The plugin tier is flat: `memory`, `session-log`, `mcp`, `sandbox`, `guardrails`, `subagent`, `hitl`, `web-search`, `skills`, `telemetry`, `cost`, and `redaction` depend on core only, and no plugin depends on another plugin. Services depend on core and on the plugin features they declare: `entity-extraction → memory` (hard, `service-entity-extraction = ["plugin-memory"]`), `replay → session-log` (hard, `service-replay = ["plugin-session-log"]`), `vector-store → memory` (hard, `service-vector-store = ["plugin-memory", "dep:wide"]`), and `speculative → session-log` (documented-optional: `ModelOrchestrator::with_session_store` records `SessionEvent::ModelSwap`); `prompt-cache`, `rate-limit` and `scheduler` declare no plugin dependency at all.

- **Direction is one-way:** a plugin MUST NOT name a service in any form: no `use crate::services::<name>`, no `cfg(feature = "service-<name>")` (including inside `cfg(all(…))`), no runtime lookup. `src/plugins/` stays ignorant that any service exists. A service→service edge requires re-tiering the shared part downward first.
- **Declare every code edge:** any compile-time reference from a service to a plugin it uses REQUIRES `service-<name> = ["plugin-<other>", …]` in `Cargo.toml`; never rely on a peer being co-enabled by accident.
- **Coordinate in core, never downward:** core MAY `#[cfg]`-reference any plugin or service; neither MUST reach a peer through a core module to dodge the two rules above. Multi-capability workflows live in core: `CucaExport::from_live` in `src/export.rs`, and `OtelCostObserver` in `src/cost_otel.rs`, the cost-ledger-to-OpenTelemetry bridge gated `cfg(all(feature = "plugin-cost", feature = "plugin-telemetry"))`.
- **No runtime peer discovery:** plugins and services MUST NOT look each other up. `CucaClient::plugins()` is an inspection accessor, not a service locator: no name matching, no downcasting. Cross-tier data moves through a caller-injected `Arc<dyn Trait>` or an explicit application hand-off (`EntityExtractionReport.delta` → `MemoryPlugin::merge_graph`).
- **Optional cross-tier behavior is documented and loud:** behavior that exists only when a declared peer is co-enabled or a peer handle is attached MUST be named in the owning module's `//!` docs, listed in the tiers above, and degrade loudly: compile-gated out of existence (`ModelOrchestrator::with_session_store`) or an explicit error (`CucaExportError::Unsupported` for a compiled-out export section). Silently doing nothing is a defect.
- **No hidden hook-order dependence:** `on_request` hooks run in registration order over one shared `UnifiedRequest`; a plugin MUST NOT require a position relative to another plugin. Where order is observable, document it at the consuming site: memory's graph/warning injections change the digest `PromptCache::lookup` computes afterward.
- **Explicit-call services:** a service is driven by direct method calls rather than pipeline hooks and MUST NOT implement `CucaPlugin` (`PromptCache`, `EntityExtractor`, `SessionReplay`, `ModelOrchestrator`, `RateLimiter`, `InMemoryVectorStore`, `Dispatcher`), so registering one is a compile error instead of an inert no-op; its `//!` header names the real entry points and any mandatory hand-off.

**Checks.** Every plugin or service feature MUST build alone on one provider (`cargo check --all-targets --no-default-features --features provider-openai,plugin-<name>` or `…,service-<name>`); CI runs that matrix across two jobs, `plugin_solo` and `service_solo`, which is how undeclared and reverse code edges are caught: `--all-features` cannot catch them. CI also greps every plugin directory for `service-` feature names, `crate::services` paths, and the `plugins::` paths the five moved modules left behind, since a `cfg(all(…))` reverse edge compiles in both the solo and all-features builds.

### Memory discipline (bounded by default)

Memory size is a first-order concern: every structure that grows with traffic ships bounded, with a stated policy at the bound.

- **Compact structures first.** Keep stream bytes in one reusable `BytesMut` scanned with `memchr` (`SseStreamParser`); pre-size known growth (`MemoryGraph::with_capacity`/`reserve`) instead of reallocating.
- **Cap every growable collection.** A new cache, log, buffer, or map that outlives one request REQUIRES a validated bound at construction, in the mold of `PromptCacheConfig::new` (rejects zero capacity), `MemoryConfig` (`max_messages`/`max_tokens`/`max_fraction`), `GraphContextConfig` (`max_nodes`/`max_relationships`), and `SandboxConfig::max_memory_bytes`. An uncapped collection is a defect unless its docs state why growth is bounded elsewhere.
- **Evict or offload at the cap.** State the at-cap policy in the owning type's docs and reuse an existing shape: TTL plus deterministic LRU eviction (`PromptCache`, `lru_order`), the ordered `CompactionStrategy` pipeline (`Offload` to a caller-supplied `VectorStore`, `Summarize`, `ClampOversizedMessages`, `SlidingWindow`), or append-only offload to disk (`SessionLogPlugin` with `FileBackend`). Unbounded growth is a defect; so is silent data loss.
- **Expose usage and warn near the cap.** A capped structure surfaces a cheap usage reading. Follow memory's seams: `ContextUsageObserver` receives a `ContextUsage` on every request (the reporting gauge), and `MemoryConfig::warn_fraction` injects a one-shot near-limit warning (idempotent via marker scan). Alerting and export belong on the caller-supplied OTel meter (`OpenTelemetryPlugin`); never install a global provider.
- **Re-verify bounds when touching hot paths.** A change to the SSE engine, compaction, a cache, or the graph MUST keep the owning module's `//!` allocation and bounds story accurate (`src/sse.rs` documents its per-frame allocations; `src/plugins/memory/graph.rs` documents its complexity envelope).
- **Local engine bounds**: the K/V block pool (`BatchingConfig::kv_tokens`, default twice `context_length`), the running sequences (`max_sequences`, at most 64), the job queue (16) and the per-request event buffer (64), the tiered-expert byte budgets (`ExpertTiers::ram_bytes`, `device_bytes`) and the Engram row cache (`EngramCache::ram_bytes`, 1 MiB to 1 TiB, default 4 GiB, 48 bytes of bookkeeping counted per row; `reader_threads` 1 to 64, default 16) are fixed at load. At the bound the engine preempts the youngest sequence, evicts the least recently used unreferenced prefix block, evicts a cooler expert, or evicts the least recently used Engram row (a row evicted before its pass uses it is read again). `LocalModel::kv_cache_bytes`, `serving_stats`, `expert_tier_stats` and `engram_stats` read the usage; `docs/content/concepts/memory-discipline.md` explains the policy. The DeepSeek-V4.1 converter streams two buffers of at most 32 MiB of f32 (measured peak RSS about 220 MB).
- **Server bounds**: request bodies 32 MiB; the latency window 60 s and 4,096 records (balancer: 1,024 per upstream); 300 one-second samples per model and for the machine; fixed atomic metrics labelled only by model, status code, upstream and GPU; 64 stats streams; 32 events buffered per chat stream; 16 models per server, 256 upstreams per balancer; one stats snapshot per upstream. A structure that grows with traffic needs a bound and its at-cap policy documented in the module `//!`; `docs/content/concepts/memory-discipline.md` lists them.
