# Repository Guidelines

## Project Overview

CUCA (**Compact Universal Client for Agents**) is a high-performance, asynchronous Rust client library intended to sit between autonomous agent orchestrators and LLM backends: an ultra-low-overhead runtime that monitors, parses, and dispatches multi-modal SSE streams. Tagline: *"Legendary vigilant witch; small footprint that constantly watches for responses."*

Current state: **implemented**. The unified client (`CucaClient`/`CucaClientBuilder`), the zero-allocation SSE parser, eight provider adapters (seven HTTP, one in-process local engine), twelve feature-gated plugins, and seven explicit-call services, including the speculative fast/slow orchestrator, are all implemented. The `server` and `server-tui` features add an application layer, the `cuca` binary: a model server, a balancer and a terminal UI over the local engine.

## Architecture & Data Flow

**Implemented:** the unified client pipeline, the SSE parser, the provider adapters, the plugins, and the services. The architecture:

- **Unified provider abstraction**: one `UnifiedRequest` in, one normalized `AgentResponseStream` out, across OpenAI, Anthropic, DeepSeek, Gemini, llama.cpp, vLLM, LM Studio and the in-process local engine (`ProviderEndpoint`, `UnifiedMessage`, `MessageContentBlock`). Every adapter maps the request's `temperature`, `max_tokens`, `top_p`, `top_k`, `seed` and `stop` (the shared part is `provider::insert_sampling`). A backend without an equivalent rejects the request with `CucaError::Config` instead of dropping the value: `top_k` on OpenAI and on DeepSeek's native route, `seed` on Anthropic and on DeepSeek's Anthropic bridge. `provider-local` is described in *Local provider*.
- **Zero-default provider policy**: no provider compiled by default (`default = []`); a `compile_error!` fires if no provider feature is enabled. Providers are opt-in Cargo features (`provider-openai`, `provider-anthropic`, …).
- **Zero-allocation SSE engine.** `SseStreamParser` is a byte state machine over `bytes::BytesMut`; inbound chunks are scanned with `memchr` in contiguous buffers, with no intermediate string allocation.
- **Plugins and services.** A plugin implements `trait CucaPlugin` (`on_request` / `on_stream_chunk` / `on_response_complete`) and observes the request/stream pipeline; it is compile-time feature-gated and carries its own non-core dependencies. A service is an explicit-call, client-level capability driven by direct method calls instead of pipeline hooks; a service MUST NEVER implement `CucaPlugin`, so registering one with `register_plugin` is a compile error rather than an inert no-op.
- **Fast/slow orchestration** (`service-speculative`): `ModelOrchestrator` + `SwappableModelPair`; complexity routing → speculative draft generation → fallback cascades on malformed output.
- **Server tier**: `server`/`server-tui` build the `cuca` binary over `provider-local` (`run`, `tui`); see *Server*.

Data flow: builder selects provider → `UnifiedRequest` passes through registered plugins (`on_request`) → provider adapter translates to vendor protocol → SSE stream parsed into `MessageContentBlock` events → each chunk passes plugins (`on_stream_chunk`) → `on_response_complete`.

## Local provider

`provider-local` (`src/provider/local/`) runs a language model in the process: pure Rust (candle on the CPU, burn and CubeCL on a GPU), no HTTP endpoint, no FFI, no llama.cpp (a design reference only). It is model-agnostic: `general.architecture` selects a row of one table, and no shared engine path may assume one model. Supported models were released in 2025 or later; code that only an older model needed is deleted, and a newly popular architecture is added through the generic loader.

- **Architectures** (`model/arch.rs`, `Arch::ALL`, 20 entries): `gemma4`, `gemma3`, `llama`, `qwen2`, `qwen3`, `phi3`, `smollm3`, `granite`, `qwen3moe`, `olmoe`, `qwen35` and `qwen35moe` (hybrid delta-net), `olmo2`, `ernie4_5`, `muse-glimmer`, `mistral3`, `mistral4` (multi-head latent attention, fused gate/up experts, ungated shared expert), `deepseek41` (hyper-connection streams, latent attention with a window and compressed sparse attention, Engram lookups, `sqrtsoftplus` MoE; CPU engine in `model/cpu/hyper.rs`, `csa.rs`, `hc.rs`, `kvquant.rs`, `engram.rs`), plus the drafter architectures `gemma4-assistant` and `mistral4-eagle`. `Behavior` flags carry the differences; the loader derives every dimension from the GGUF metadata and tensor shapes. An unknown architecture, tokenizer or `tokenizer.ggml.pre` fails naming the value. The GPU engine (`model/gpu.rs`) runs every model architecture; `deepseek41` goes through `model/gpu/hyper.rs` and the kernels `hc_kernel.rs`, `csa_kernel.rs`, `topk_kernel.rs`, `qdq_kernel.rs` and the MXFP4 formats of `moe_kernel.rs`, on one device (tensor parallelism is rejected, `gpu_layers` only at cuts that keep each cache source with its readers).
- **GGUF** (`gguf/`): the crate owns its reader, because candle's fails on tensor types it does not implement. `GgufType` adds MXFP4 (id 39, 17 bytes per 32 values: E2M1 nibbles and an E8M0 scale), NVFP4 (id 40, 36 bytes per 64: four UE4M3 scales per 16 values), IQ4_NL, IQ4_XS, IQ2_XXS, IQ2_XS, IQ2_S, IQ3_XXS, IQ3_S, IQ1_S, IQ1_M, TQ1_0, TQ2_0 and I8 to candle's float, legacy and K-quant types, and keeps an unrecognised id as `Unknown(id)` so a header with it still opens and only that tensor's request fails, naming tensor and type. Versions 1 to 3, `general.alignment` honoured. `model/quant.rs::dequant_row` decodes every type but Q8_1 in place (Q8_1 goes through candle), bit-exact to ggml: the K-quants in `quant/kquants.rs`, the I-quants, TQ and FP4 types in `quant/iquants.rs`, the I-quant grids in `quant/iq_tables.rs` (ported from llama.cpp `ggml-common.h`, cross-checked against gguf-py by `testdata/quants/make_tables.py`). `quant::unpack_block` gives a block's integer quants with folded sub-scales, per-group scales and minima (`quant/block.rs` `Unpacked`, folding bounds in its `//!`), the contract the CPU and GPU kernels decode by. `testdata/quants/quants.bin` (from `make_fixture.py`, gguf-py's dequantizers) pins every type bit for bit. A split set (`split.no`, `split.count`, metadata in part 1) opens as one `Content`; the parts may sit on different volumes.
- **Generic mechanisms**: `Behavior` flags `hyper_connections` (HC residual streams, `model/hc.rs`), `compressed_attention` (compressors, indexer, candidate blocks, kv and index source layers, attention sinks, grouped output projection, `model/csa.rs`, `kvquant.rs`), `engram` (per-layer token embeddings, `model/engram.rs`, `engram_io.rs`) and `moe_ext` (`sqrtsoftplus` router, selection bias, SwiGLU clamps) gate these paths from the GGUF metadata; no shared path tests for `deepseek41` by name, and another architecture that sets a flag gets the mechanism. `deepseek41` sets all four plus `kv_qdq`.
- **Gemma 4 mixture of experts** (`gemma4` with `gemma4.expert_count` above 0, the 26B-A4B; CPU engine only, the GPU engine rejects it): `Behavior::moe_if_experts` lets the file decide whether the FFN is a mixture of experts, `Behavior::dual_branch_moe` gives the layer its dense gated FFN beside the routed experts (`post_ffw_norm(post_ffw_norm_1(dense(ffn_norm(x))) + post_ffw_norm_2(experts(pre_ffw_norm_2(x))))`; router on `rmsnorm(x) * ffn_gate_inp.scale / sqrt(n_embd)`, softmax over all experts, top-k, renormalised, each weight times `ffn_down_exps.scale`; fused GELU gate/up experts, `DualFfn` in `model/cpu.rs`), and `LayerLayout::v_from_k` reads a layer without `attn_v` as K-as-V (the full-attention layers). The tiny release-format builder is `TinyGemma4Moe` (`model/tiny.rs`); `model/cpu/gemma4_moe_tests.rs` holds the gated oracle against transformers (`oracle.g4moe.oracle_dir` in `cuca-test.kdl`) and the real-file checks against llama.cpp (`oracle.g4moe.real`, `real_ref`, `trunc` and `trunc_ref`).
- **Engram**: `per_layer_token_embd` (hashed n-gram rows; token ids go through the compressed token map, multipliers and prime buckets come from `ple.*` metadata) stays in the GGUF and is read by `EngramCache::reader_threads` positional readers (1 to 64, default 16), sorted by file offset, at pass entry and for the next prefill chunk. An LRU of `EngramCache::ram_bytes` (1 MiB to 1 TiB, default 4 GiB; a row counts its file bytes plus `ENTRY_OVERHEAD` 48) holds the rows as the file stores them, allocated in segments as it fills. At the bound the least recently used row is evicted, a row evicted before its pass uses it is read again, and output never changes. `LocalModel::engram_stats` returns `EngramStats`; a model split by `gpu_layers` shares one table. Set as `LocalModelConfig::engram`, in KDL `engram ram_bytes="2g" reader_threads=8`.
- **Pipeline**: the tokenizer (`tokenizer/`: SentencePiece `llama`, byte-level BPE `gpt2` with hand-written pre-tokenizers per `tokenizer.ggml.pre` including `tekken`, `deepseek-v3` and `joyai-llm` (a three-split chain), and the `gemma4` scheme) and the chat template (`chat/`: the GGUF's Jinja through minijinja) come from the file. `LocalModelConfig::chat_template` (the text), `LocalModelConfig::chat_template_file` (a path; an unreadable file is `CucaError::Io`) or `ModelPreset::template` replaces the template, in that order of precedence, and the names `mistral-v7`, `mistral-v7-tekken` and `deepseek-v41` expand to builtin Jinja. `ChatFormat` derives the end-of-generation ids, the reasoning markers and the tool-call syntax (`ToolSyntax::Dsml` for DeepSeek-V4.1, parsed by `parse_dsml_calls`); a template that reads `reasoning_budget` thinks unless the request disables it, with `low` for a minimal or low effort and `high` above. `OutputParser` (`output/`) emits `Text`, `Thinking` and `ToolCall` blocks.
- **Sampling** (`sampling.rs`): for each of temperature, `top_k` and `top_p`, the request wins over `SamplingConfig`, which wins over the file's `general.sampling.*` keys, which win over the built-in default. A request `seed` wins over `SamplingConfig::seed`; the request's `stop` strings end a reply before their first occurrence (`engine/stop.rs`).
- **Sources** (`ModelSource`): `HuggingFace` (pinned revision, resumable download, SHA-256, optional split `parts` and pinned `template`), `File`, `Checkpoint { repo, revision }` and `Dir`. A safetensors checkpoint is converted once to a cached GGUF by `convert/`, a pure-Rust port of llama.cpp's `convert_hf_to_gguf.py` (`LocalModelConfig::convert.quant`: `f16`, `q8_0` default, `q4_0`, and the K-quant mixes `q4_k_s`, `q4_k_m`, `q5_k_m`, `q6_k`, whose per-tensor types port llama.cpp's `llama_tensor_get_type` in `convert/quantmix.rs` and whose blocks come from ggml's reference quantizers ported in `convert/refquant.rs`, because candle's differ; no importance matrix; FP8 weights are dequantized while converting). Split GGUF files (`<base>-00001-of-0000N.gguf`) open natively with `gguf::Content::open_with`: the parts are looked for next to the named file and in `LocalModelConfig::shard_dirs`, a split Hugging Face download keeps its parts in the cache, and nothing is merged or copied. `ModelSource::PRESETS` is `PRESET_TABLE` (32 entries: 30 models and 2 drafters, each pinned to a commit and SHA-256, none for `deepseek41`; the `q4_k_m`, `iq4_xs` and `iq2_xxs` presets are unsloth files, the Gemma ones pinning Google's template); the first, `gemma4-e2b-q4_0`, is the default. A string parses as a preset name, `repo:revision:file` or `repo:revision`.
- **Configuration**: `LocalModelConfig` and every type in it implement `serde::Deserialize`, and the KDL keys are the Rust field names (`examples/configs/local_model.kdl` lists every key). `source` is a preset name, `"repo:revision:file"`, `"repo:revision"`, `file="..."`, `dir="..."`, a `checkpoint` block or a `hugging_face` block; `device "vulkan:0"` and `shards "vulkan:1"` name the devices; `batching`, `experts` (`"resident"`, `{ tiered ... }`, `{ host layers=4 }`), `engram`, `convert`, `drafter` (`"in-trunk"` or any source) and `sampling` are tables. Sizes take an integer or `"512m"`, `"4g"` (powers of 1024). `cache_dir: None` is the platform cache directory (`%LOCALAPPDATA%\cuca`, else `%USERPROFILE%\AppData\Local\cuca` on Windows; `~/Library/Caches/cuca` on macOS; `$XDG_CACHE_HOME/cuca`, else `~/.cache/cuca` elsewhere), and `hf_token: None` or an empty token is an anonymous download. The library reads no other environment variable. `shards` and `shard_dirs` accept one value or several.
- **DeepSeek-V4.1 conversion** (`convert/deepseek41/`: `plan.rs`, `stream.rs`, `meta.rs`, `hparams.rs`; `convert/engram.rs`): `ModelSource::Checkpoint { repo: "deepseek-ai/DeepSeek-V4.1-Flash-1017", revision }` (FP8 dense, FP4 experts, 510 GB of shards) converts once to a split set next to the nominal `model-<quant>.gguf`: `-00001-of-00003` metadata only, `-00002-` backbone, `-00003-` `per_layer_token_embd` (2 parts without Engram layers), parts 2 and 3 renamed before part 1 so part 1 marks a finished set; the DSpark stages go to `dspark-model-<quant>.gguf`. Matrices follow `quant` (dense FP8 becomes Q8_0 at the default `q8_0`), FP4 experts repack byte-wise to native MXFP4, `quant = f16` dequantizes exactly to F16, hc, router, sink and norm tensors are F32, `conf_proj.weight` is a 1-D vector, the vision tower, aligner and `ffn.gate.bias_vl` are skipped. `ConvertConfig { quant, engram_quant }`, `EngramQuant::{Q8_0 (default), Q4_0, Bf16}` (exported from the crate root); a non-default `engram_quant` adds `-engram-<name>` to the cached file name. Sizes: backbone 297.96 GB, Engram table 208.90 GB at Q8_0 (about 110.6 GB at Q4_0, 393.2 GB at Bf16), drafter 7.91 GB. A free-space check of the output volume (`fs4::available_space`; skipped where the platform reports none) fails with `CucaError::Config` before any write. The stream holds two buffers of at most `BLOCK_ELEMS` (32 MiB of f32); measured peak RSS about 220 MB, release build, this checkpoint, default precision, I/O bound (2 h 44 min for the 507 GB set on an HDD-class volume at about 52 MB/s). `convert/engram.rs` ports numpy's `SeedSequence`/`PCG64` hash multipliers and uses `tokenizers` normalizers for the compressed token map. Verified: unit and e2e tests, the gated oracle test against the tiny torch oracle (`oracle.ds41.oracle_dir`; bit-exact tensors and metadata), and a conversion of the real release checkpoint whose header matches ggml-org's published headers (62 of 62 metadata keys, 1003 of 1043 tensor names, identical shapes, only documented dtype differences). The Engram Q8_0 error on the real table is not measured.
- **Devices**: `LocalDevice` is `Cpu` (default), `Vulkan`, `Metal`, `Cuda` or `Rocm`, enabled by `provider-local-gpu` (the shared engine, no backend alone) plus `provider-local-vulkan`, `-metal`, `-cuda` or `-rocm`. Every variant exists in every build: a device whose feature is off fails `LocalModel::load` with `CucaError::Config`, one that cannot be opened with `CucaError::Provider`. There is no automatic selection. On a GPU every quantized matmul weight (legacy, K-quant, I-quant, TQ, MXFP4, NVFP4, Q8_K), dense and expert, stays in the file's blocks, zero-padded to whole `u32` words and stored word-major (`model/moe_kernel/native.rs`; the format is a comptime kernel argument, the I-quant grids one small device tensor per load); F32, F16 and BF16 upload as f32; only Q8_1 is requantized to Q8_0 at load. A tensor-parallel cut inside a block requantizes that matrix to Q8_0.
- **GPU placement**: `gpu_layers` puts the last `n` layers and the head on the GPU and the first layers and the embeddings on the CPU (`model/split.rs`). `device` plus `shards` (`device "vulkan:0"`, `shards "vulkan:1"`) split a model over several GPUs (`model/tp.rs`; all-reduce through NCCL on CUDA, host-staged in shard order elsewhere); it rejects drafters, tiered and host experts, delta-net layers, latent attention (`mistral4`) and full-width Q/K norms (`olmo2`, `olmoe`) with `tensor parallelism: ...`.
- **Layer stages**: a model can run as a chain of engines over layer ranges (`LayerRange`, `Part`, `Carry`, `forward_stage` in `model/split.rs`; `gpu_layers` is its two-stage case on one machine). `remote_stage url="http://box:8000" layers=14` nodes (in layer order from layer 0) make a coordinator: `Model::Chain` (`model/chain.rs`, `ChainModel`) runs the remaining layers and the head on its own device and relays each worker's `Carry` to the next through a `StageTransport` (`HttpTransport` upgrades a connection to a frame stream at `/cuca/v1/stage-stream` and posts a frame to `/cuca/v1/stage` where it cannot, see *Stage frame stream*; both block the engine thread). `stage first=0 layers=14` makes a worker: an engine whose `Model` holds only those layers answers the frames of `stageframe.rs` through `LocalModel::stage_call` (`engine/stage.rs`: `open` checks the file fingerprint, layers and sizing and starts a session, and `forward` is the one call of a step, see *Stage step calls*) and serves no request (`is_stage`, `tokenize` refuses). The coordinator's engine owns the block tables, the prefix store and the sequences and sends each sequence's tables with every forward call, so every node's pools use the same block ids; a worker keeps K/V and recurrent state for its layers per slot, plus the tokens before each slot's next position for Engram layers. Any failed stage call fails the step; the engine then fails the running requests and empties its pools as for any failed pass, and the next call opens a new session on every worker. Boundaries must be in `legal_cuts` (compressed attention forbids cutting between layers that share compressed rows or indexer picks), the last stage keeps the head so logits never cross the network, drafters pair with a chain as *Chain speculation* says, and K/V transfer and `gpu_layers` are not combinable with stages. The stage tests are `cpu_stages_equal_the_whole_model_at_every_cut` (bit for bit at every legal cut), `a_chain_over_loopback_stages_equals_the_whole_model`, `a_failed_stage_fails_the_step_and_the_next_request_reopens` and the GPU-gated `gpu_stages_match_single_device`.
- **Stage step calls**: a step costs one `forward` call per remote stage; the calls that used to follow or precede it ride in the frame (`StageSeq::restore`, `rewind`, `snapshot`, `prefetch`; ops 3 to 5 no longer exist). The scheduler hands the model what it knows when it plans a step (`StepHint`: the next prompt chunk of a sequence still prefilling, and whether a snapshot is taken at the end of this chunk) through `Model::forward_batch_hinting`; a model that is not a chain reads the Engram rows ahead after the pass itself, a chain sends them in the frame to the stages that hold an Engram layer and reads its own. `ChainModel::restore` restores the local stage at once and records a pending `Restore` for the slot, which the slot's next forward frame carries (the worker restores before the pass); a snapshot id a pending restore names is held back from `drops` until the restore has been sent. `ChainModel::rewind` does the same for a rollback inside the slot's last verification call: the local stage goes back at once and a pending `rewinds` entry rides in the next frame as `StageSeq::rewind` (the worker rewinds before the restore and the pass, and refuses when its state returns elsewhere); every pending entry is cleared by a restore, a reset, a reopen and a successful call. A forward frame whose hint asks for a snapshot makes each worker keep a copy under a fresh id after the pass and answer its size (`forward_reply`); `ChainModel::snapshot` then adds the local stage's, and returns `None` for a slot whose last call took none. `open` is answered with the worker's `rollback_rows` (`ok_reply`, `decode_open_reply`; `usize::MAX` for an attention-only worker). `WIRE_VERSION` (4) is in the model fingerprint a worker checks at `open`, so builds with other layouts refuse each other there. Test: `a_step_costs_one_call_per_stage` (Qwen 3.5 and DeepSeek-V4.1 chains with 16-token chunks: one call per scheduler step, no op but `forward` after the open, the restores, snapshots and prefetches seen in the frames, replies equal the whole model's); before, a 40-token Qwen 3.5 prompt took 7 calls for 5 steps and a 70-token DeepSeek-V4.1 prompt 12 for 8.
- **Stage measurement**: every remote stage's `StageTransport` owns a fixed set of atomics (`StageCounters`, `model/chain/stats.rs`): answered calls, failed calls, wall nanoseconds, the worker's compute nanoseconds and frame bytes both ways (the same on the stream and `POST` transports: no length prefix or reply head). `HttpTransport` times each call; the worker answers with the time its engine thread took (`StageReply::compute` from `LocalModel::stage_call`) in `STAGE_COMPUTE_HEADER` (`x-cuca-stage-compute-ns`) over `POST` and in the compute field of the reply head over the stream (a worker that omits it counts zero compute), and network is `wall - compute`, including the worker's queue wait. `LocalModel::stage_stats` returns `StageStats` per remote stage; the server renders `cuca_stage_calls_total`, `cuca_stage_errors_total`, `cuca_stage_seconds_total{part="compute|network"}` and `cuca_stage_bytes_total{direction}` labelled by the stage's index, and `ModelStats::stages` carries the means.
- **Stage call repeats**: `HttpTransport` sends a call again, once, when the connection is lost before a byte of the answer arrived (over `POST`: a `send` that fails with a request error that is neither a connect error nor a timeout, `lost_connection`, on a pooled connection kept by `pool_max_idle_per_host(1)`, `POOL_IDLE_TIMEOUT` 30 s; over the stream: a dead socket, see *Stage frame stream*): a connection the server closed, which the engine thread does not see between passes, or a worker that died after running the frame. That is safe because every frame after `open` carries `seq`, its number in the session (`Remote::next_seq` in `model/chain.rs`, from 1, reset by `open`), and the worker runs a call once (`Engine::once` in `engine/stage.rs`): it keeps the last `seq` and its reply (a `Bytes`, one frame), answers the same `seq` with it, runs nothing, and refuses a smaller or zero one. Without that a repeated pass is not safe: a hybrid model refuses it (position mismatch) and a hyper-connection model at an odd position (compressor state), and a refusal fails the step. `open` is repeatable as it is. `LocalModel::stage_call` returns `StageReply { frame: Bytes, compute }`; retries count in `StageStats::retries` and `cuca_stage_retries_total`. Tests: `a_lost_answer_leaves_the_chain_equal_to_the_whole_model` (every call of every architecture lost once and sent again, via `Loopback::lose_every_reply`), `a_worker_answers_a_repeated_call_from_memory`, the `http.rs` transport tests (`calls_reuse_their_connection`, `a_connection_that_dies_before_the_answer_gets_the_frame_again`, `a_second_failure_is_the_calls_error`, and for the stream `a_stream_that_drops_before_the_answer_is_replaced_and_the_frame_sent_again`, `a_second_dropped_stream_is_the_calls_error`) and `a_stage_answer_lost_on_the_wire_is_retried_and_the_reply_is_unchanged` (a cutting proxy between a coordinator and a worker server, over the stream).
- **Stage frame stream** (`model/chain/stream.rs`, `stagestream.rs`, `server/socket.rs`): over plain `http://` a coordinator's `HttpTransport` sends `GET /cuca/v1/stage-stream[/{model}]` with `Connection: Upgrade`, `Upgrade: cuca-stage/1` and the bearer key, and the worker's `auth` and `observe` middleware treat it like any route. The worker answers `101` (426 without the `Upgrade` headers, 409 `stage_mismatch` for a model that is no layer stage, 503 when `MAX_STAGE_STREAMS` = 8 streams are open) and the connection then carries raw frames: a request is `len u64 LE` and the frame, a reply is `status u8` (0 answered, 1 `CucaError::Config`, 2 any other failure), `compute_ns u64`, `len u64` and the payload (the message for a status other than 0). The coordinator sends nothing before it has read the `101`; bytes pipelined behind the upgrade request are lost. Each side reads and writes the socket on a thread that already exists, because the wake-ups between runtimes were most of the cost (HTTP: 0.50 ms of network per decode call over loopback; stream: 0.19): the coordinator's engine thread (`StreamLink`, a blocking `std` socket), the worker's thread of that connection (`LocalModel::serve_stage_stream`), which reads a frame, queues a `Msg::Call` for the engine thread and waits, while the engine thread writes the reply itself (the worker's engine thread never blocks on a socket read). One frame is in flight per connection and a frame's length is checked against `MAX_STAGE_FRAME_BYTES` (1 GiB) before it is read. `server::socket::ServedListener` (the listener of `serve`) gives every accepted connection `TCP_NODELAY` and a `RawSocket` claim (connect info of the request), since hyper's upgraded stream cannot be unwrapped (hyper-util's auto builder hides it in a private type): the handler marks the claim wanted before it answers `101`, and when hyper drops the upgraded connection the tcp stream moves into the claim instead of closing; the handler then takes it out of the runtime (`into_std`, blocking). `STAGE_STREAM_IDLE` (300 s) read and `STAGE_STREAM_WRITE` (60 s) write timeouts end a dead peer, and the stream's place is released before its socket is shut down, so a coordinator that reconnects at once is not refused. A connection that dies before the first byte of the reply (EOF, reset, broken pipe) is reopened and the frame sent again once (`stats.record_retry`); a timeout is not, and a status reply keeps the connection. The counters count frame bytes on both transports (not the length prefix or reply head). `HttpTransport` posts instead for an `https` URL, and after a refused upgrade: for good on 400, 404, 405, 426, 501 or an answer that is no HTTP (an older worker, a proxy that strips `Upgrade`), for that call on any other. Tests: the `stream` tests in `chain/http.rs` (`calls_use_one_upgraded_stream`, `stream_failures_keep_the_connection_and_map_to_errors`, `a_server_without_the_stream_is_posted_to_from_then_on`, `a_busy_worker_is_posted_to_for_that_call_only`, `a_silent_stream_times_out_and_is_not_sent_again`, `an_answer_above_the_frame_limit_is_refused_unread`), `the_stage_stream_route_upgrades_authenticates_and_is_bounded` (401, 426, 409, 101, a bad frame, an oversized frame, the stream cap) in `server/http.rs` and the `socket.rs` claim tests.
- **Stage carry type** (`RemoteStage::carry`, `CarryDtype` in `provider/local/mod.rs`; KDL `remote_stage carry="f32"|"bf16"|"f16"`, default `f32`, per stage): the type every float of a carry (hidden, per-layer, pre, mirrored K/V rows) is written in, both directions. `f32` is bit-exact; `bf16` and `f16` are two bytes each (`half`, round to nearest even; `Writer::put_floats` and `Reader::get_floats` in `wire.rs`) and **not bit-exact**, which every doc and message must say. `f16` refuses a finite value above 65504 (`put_floats` fails, so the call and the step fail) rather than send infinity. `Open::carry` names the session's type (added with wire version 3; the version is now 4, shared with K/V transfer); a worker keeps it in `StageHost::carry` and answers in it; every carry starts with a type tag, so frames decode alone, a worker refuses a forward carry in another type than its session's, and `decode_forward_reply(bytes, expect)` refuses a reply in another type. `StageTransport::carry` gives the coordinator a stage's type (`HttpTransport` from the config, `Loopback` in tests). Integers (tokens, tables, positions) never round; only the hidden-state bytes halve (the first worker receives none). Measured on `q8_0` files only (Qwen3 0.6B at layer 14, Qwen 3.5 0.8B at 12): bytes halve; network per prefill call is unchanged on loopback and 7.5 ms to 3.5-4.2 ms behind a loopback proxy paced to 1 Gbit/s, 69 ms to 30-35 ms at 100 Mbit/s; the logits differ from the `f32` chain's by 0.3 to 0.55 at most (1 to 1.7 % of the largest) before the first greedy token that differs, which with quantized weights is the engine's floor under any carry change (8-bit activation quantization re-rounds: a 1e-7 relative perturbation of the `f32` carry gives the same), so `f16` was not measurably closer than `bf16`; float-weight files were not measured. Tests: the `wire.rs` float tests, `a_reduced_carry_is_half_the_bytes_and_within_rounding` and `the_carry_type_rides_in_open_and_in_forward_frames` (`stageframe.rs`), `reduced_carries_stay_near_the_whole_model` (`model/split.rs`: every architecture, a loose bound that catches a wrong carry, not an imprecise one), `a_chain_over_reduced_carries_runs_in_fewer_bytes` (`engine/mod.rs`, a hybrid model too) and the `remote_stage` config parse test.
- **Chain speculation** (`model/mtp.rs` `Drafter::head_target`, `model/chain.rs` `ChainModel::check_drafter`, `rollback_rows`, `rewind`): a drafter that keeps a cache of its own (in-trunk head, EAGLE) drafts and observes against the chain's last stage (`Model::local_cpu`: the drafter pairs with the coordinator's layers, so both must be on the CPU), and the Gemma 4 assistant reads that stage's K/V as before. The final-norm hidden rows (`Hidden::PostNormAll`) come from the local stage; the token embedding comes from it too, and `Transformer::keep_embedding` loads the table there when the head is untied (`Model::chain_of(.., embedding, ..)`, true whenever the engine has a drafter). A verification round is one forward call per worker with `Want::All` over `k + 1` rows. An attention-only chain rolls back by length (K/V is positional: `ChainModel::rewind` returns it and the next call overwrites the rejected rows). A chain with recurrent (delta-net) or compressor (hyper-connection) state rolls back through the workers' own verification record (`Transformer::rewind`, `Slot.verify`, kept for a `Want::All` call of 2 to 17 rows on a CPU stage; `ChainModel::hybrid` is the model's flag, not the last stage's): `rollback_rows` is the least of the local stage's and every worker's `open` answer (17, or 1 for a stage with no record such as a GPU stage with delta-net layers), and a position inside the last call goes back through `StageSeq::rewind` (see Stage step calls). The coordinator cannot see what a worker kept, so `ChainModel::verify` tracks each slot's last verification call `(first, rows)` and `rewind` accepts only a position past `first` (or `first` itself when it is even on a hyper-connection model: a half-pooled pair cannot be restored at an odd start) and below `first + rows`; any other position, and 0, resets the slot as before (the worker then starts over at position 0). A hyper stage rewinds by its pooled pairs only when a layer of its range owns a ratio-2 compressor (`HyperModel::pools_pairs`, `HyperState::pools_pairs`: structural, from the stage's `LayerRange`); a stage without one takes only its position back, and the first non-empty log tells the pairs of one that has some. `check_drafter` refuses a head drafter when `rollback_rows` is 1. DFlash and DSpark are refused at `stage::check_stages` (config) and `Drafter::head_target`: they read `Hidden::Layers` of several target layers (`target_layer_ids` such as `[1, 13, 25, ...]`), which a worker's reply does not carry, and a stage's `StageSeq` cannot request (a wire extension would be needed). Tests: `speculation_on_a_chain_equals_plain_greedy` (`engine/mod.rs`: EAGLE on a tiny `mistral4`, the in-trunk head on a tiny attention-only `qwen35` and on the hybrid `qwen35` with one and two workers; equal to plain greedy, drafts and accepted counts equal to one node's, the head one pair behind the cache, with and without lost answers, fewer calls than tokens), `a_chain_rolls_back_a_verification_round_like_the_whole_model` (hybrid `qwen35`, one whose last layer is attention, and `deepseek41`, with one and two workers and a coordinator cut anywhere: logits after every rollback position equal the whole model's), `a_second_rewind_to_an_odd_position_below_the_call_resets`, `a_failure_in_a_speculative_round_fails_one_request` (every forward call of a clean run, EAGLE and hybrid in-trunk) and `a_chain_refuses_the_drafters_it_cannot_serve` (a worker that answers rollback 1, and DFlash).
- **K/V transfer** (`LocalModelConfig::kv_export`, `model/transfer.rs`, `kvframe.rs`, `engine/scheduler/transfer.rs`, `kv.rs`): a prefill node runs a prompt as a sequence that ends at its prefix and leases the blocks (`LocalModel::kv_export` yields a header with the wire version, the `LocalModel::fingerprint` of the files and cache layout and the range, then `PoolRows` frames in chunks, the recurrent snapshot of a hybrid model and an end frame); a decode node asks `kv_hit` how much its store holds and files the rest through `KvImport` (`Engine::import_frame`, `KvPools::adopt`: rows are written before the blocks are named, so a lookup never finds an unwritten block, and a bad frame gives the blocks back). Rows travel in one canonical layout (`[n_kv_head][rows][head_dim]`, no V for latent or `kv_is_value` layers, compressed rows in `k`) that the CPU and GPU engines read and write (`Model::{export_rows, import_rows, snapshot_export, snapshot_import}`, tested by `gpu_exported_rows_import_on_the_cpu_and_back`). An import needs the prefix store and no observing drafter (`imports_kv`), and K/V transfer is not available with layer stages or tensor parallelism.
- **Experts**: `ExpertPlacement` is `Resident` (default), `Tiered(ExpertTiers { ram_bytes, device_bytes, loader_threads, warm_from })` (`model/tier.rs`: routed experts stay in the GGUF and load on demand through byte-bounded caches with learned heat; missing experts of a layer that are adjacent in the file, when its gate, up and down tensors store expert after expert, are read as one run of at most 4 per matrix) or `Host { layers }` (GPU only: routed experts stay in RAM and the CPU computes them; not combinable with tiers or shards). Output equals the resident mode's on the same device.
- **K/V and batching**: K/V lives in blocks of 16 positions (`model/paged.rs`) named by token ids, with a prefix store, so `prompt_cache_usage.read_tokens` is a multiple of 16. The step scheduler (`engine/scheduler.rs`) runs up to `BatchingConfig::max_sequences` requests (1 to 64, default 4) in one forward pass per step over one K/V pool (`kv_tokens`, default twice `context_length` on the CPU and `context_length` plus at most 4,096 on a GPU, the memory knob), preempts the youngest sequence when the pool is full, and reports through `LocalModel::serving_stats`. On the CPU a sequence's output equals what it produces alone, bit for bit. A compressed group of rows (`deepseek41`) has `stride` tokens per row, so a block spans `16 * stride` tokens and prefix hits are multiples of the largest stride.
- **CPU kernels**: every quantized matmul weight, MoE and tiered experts and drafters included, runs through the batch-invariant row-batched kernel (`model/qmm.rs`, `QmmWeight::from_raw(GgufType, bytes, n, k)`): legacy Q4_0 to Q8_0, Q2_K to Q6_K, Q8_K, the I-quants, TQ1_0, TQ2_0, MXFP4 and NVFP4 (Q8_1 is not served). One `Format` trait maps each type onto 32-value entries: `i16` quants with integer sub-scales folded in, an f32 scale and up to two per-16 minima against exact half sums of the activation block. `QMatMul` is `Float` (candle, per row under `RowExact`) or `RowBatched`; candle never multiplies a quantized weight. The token embedding keeps its file blocks and dequantizes the looked-up rows. A dtype MUST NOT dispatch to different kernels by row count: a row's bits must not depend on the batch size. The kernel decodes four weight rows into `i16` lane pairs once and multiply-adds them against every activation tile (`wide`: one `vpmaddwd` and sixteen `f32` lanes per block pair under `-C target-cpu=native`), and quantizes the activations over the pool; its result equals the module docs' scalar definition bit for bit (`the_kernel_equals_the_scalar_definition_bit_for_bit`).
- **Drafters** (`LocalModelConfig::drafter`, `draft_tokens` 1 to 16): `DrafterSource::File` loads the Gemma 4 MTP assistant, the Mistral Small 4 EAGLE head, a DFlash block drafter or the DeepSeek-V4.1 DSpark drafter (`dflash` GGUF with `dflash.hyper_connection.count`, `model/cpu/dspark.rs`: stages of the target's own block kind with window-only attention, blocks of 5 drafted at once from the target's hidden features, a Markov head biasing each row's logits and a confidence head); `InTrunk` uses a head inside the target's own file (Qwen 3.5). The EAGLE, DFlash, DSpark and in-trunk drafters are CPU only. Every running sequence drafts and verifies in the shared step (not in a step where a sequence prefills), with one `Governor` and `CostModel` per concurrency class (`spec_class`: 1, 2, 3 to 4, 5 to 8, up to 33 to 64 decoding sequences). A drafter that observes every position (`Drafter::observes`: in-trunk, EAGLE, DFlash, DSpark) keeps one cache per state slot, `Engine::drafters`, forks that share one set of weights (`Drafter::fork`), and a prompt takes the free slot whose cache shares the longest prefix with it (`Engine::pick_slot`); the Gemma 4 assistant reads the target's K/V and is shared. A draft takes only blocks the pools have left after every sequence's own row (`KvPools::fits`), so it never preempts a sequence. Speculative output equals plain greedy output.

## Server

`server` (`src/server/`, binary `src/bin/cuca.rs`) is an application layer above core and `provider-local`; `server-tui` adds the terminal UI in `src/server/tui/`. It serves `LocalModel`s over an OpenAI-compatible HTTP API (axum), balances several servers, and reports telemetry. Tier rules: it depends on core and `provider-local` only, never on a plugin or a service; no other module names `crate::server`; `server` enables `provider-local`, so it satisfies the provider gate; the library returns `ServerError` (no `anyhow`), and the binary only parses `--config` and loads the file.

- **Model server**: `serve` loads models concurrently (`registry.rs`), answers `/health` 503 until all are ready and exits on a failed load. Chat requests go through `LocalModel::generate` (`LocalGeneration` and `GenerationReport`: exact usage, finish reason, queue seconds), not `CucaClient`, because the client path reports neither the finish reason nor per-request timings and would copy every block. `openai.rs` holds the wire mapping and rejects what the engine cannot honour (`n`, `logprobs`, penalties, `logit_bias`, `response_format`, image parts) with a 400 naming the field; `/v1/completions` is absent because the engine has no raw prompt path. A client disconnect drops the stream task, which drops the `LocalGeneration` and cancels the engine request.
- **Stage and K/V routes**: a model with `kv_export` answers `POST /cuca/v1/kv/export`; a layer-stage worker answers `POST /cuca/v1/stage` (`/cuca/v1/stage/{model}` with several models) and `GET /cuca/v1/stage-stream` (`/cuca/v1/stage-stream/{model}`, an upgrade, see *Stage frame stream*) through `LocalModel::stage_call` and is left out of `/v1/models`, so no balancer routes chat to it. A worker's `CucaError::Config` is a 409 `stage_mismatch`, any other failure a 500 `stage_failed` (over the stream: status 1 and 2). The coordinator reads a 409 to `open` as a configuration error (naming the stage) and a session mismatch on any later call as a restart of the worker: a provider error, `stage {url} restarted and lost this sequence's state`, after which the engine fails the running requests and the next call opens a new session.
- **Sockets**: `server::socket::ServedListener` is the listener of `serve` and `server::nodelay` that of `balance` (`axum::serve::ListenerExt::tap_io`): every accepted connection has `TCP_NODELAY`, which axum 0.8 does not set; reqwest 0.13 defaults its clients to it, and `HttpTransport` sets it explicitly on both its transports. A `ServedListener` connection's IO also carries a claim for a stage stream's upgrade (*Stage frame stream*; an unclaimed connection closes with its IO as usual), so `serve` is started with `socket::serving`, which adds the connect info; a router served any other way answers an upgrade with a 500.
- **Configuration**: `cuca run` takes one flag, `--config <FILE>` (default `cuca.kdl`), and starts the sections the file has; `cuca tui` keeps `--url`, `--api-key` and `--interval-ms` and reads no file. `CucaConfig` (`config.rs`: `log`, `serve`, `balance`, all optional) is the file: `log format="pretty"|"json" level="info,cuca=debug"` (`LogConfig`), `serve { listen, api_key, stats_api, latency_window, model "name" { <LocalModelConfig keys> } ... }` (`ServerConfig`; a model's name defaults to its preset name, else the Hugging Face file stem, the checkpoint repo name, the file stem or the directory name) and `balance { listen, upstreams "url" "url", upstream_api_key, api_key, policy, health_interval "1s" (100 ms to 60 s), latency_window, stats_api }` (`BalancerConfig`). An unknown key is an error naming the key (and the model). Secrets use `${VAR}` placeholders against the file's `variables { }` block, then the environment (`examples/configs/cuca.kdl`).
- **Entry point** (`server::run(Option<ServerConfig>, Option<BalancerConfig>)`, the only public way to start the tier; the binary applies `log` with `init_logging` first): neither section is a `ServerError::Config`; `serve` alone runs `serve_until`, `balance` alone `balance_until` (needs `upstreams`), each until `shutdown_signal`. With both, `colocate` rejects port 0 in `serve.listen`, equal listeners and `balance.upstream_api_key != serve.api_key`, then `BalancerConfig::add_local_upstream` prepends the server's address (loopback for an unspecified IP) unless listed, and `serve_and_balance` stops both through a `watch` channel when either ends or a signal arrives, returning the first error. Topology: each machine's `upstreams` names other machines' `serve` ports, never a balancer, so a request is forwarded at most once.
- **Telemetry**: `metrics.rs` renders Prometheus text by hand over fixed atomics and histograms; `latency.rs` is the sliding window of finished requests; `collector.rs` samples each model's `ServingStats` and the machine every second into 300-entry rings and builds the `StatsSnapshot` (`stats.rs`, the serde wire types shared with the balancer and the TUI, `#[serde(default)]`, fields added and never renamed); `diagnosis.rs` is a table of data-driven rules with `Thresholds`. The system sampler is the core-tier module `src/sysmon/` (feature `sysmon`, which `server` enables; sysinfo, NVML, WMI on Windows, sysfs on Linux, ioreg on macOS); it owns the `SystemSnapshot` wire types and never names `crate::server`.
- **Balancer** (`balancer/`): `routing.rs` (pure: candidates, load score, rendezvous hashing, the fallback rule `score > 2 * min + 2`, `weighted_score` scaling a slower candidate to `(score + 1) * fastest / speed - 1`), `state.rs` (`candidates` applies the weighting and leaves `Role::Prefill` upstreams out unless nothing else serves the model; `proxy.rs` names a prefill node to a `Role::Decode` upstream in `x-cuca-prefill`), `upstream.rs` (pollers, health, ejection, backoff, one speed per listed model, `1 / latency.itl.mean`, kept while the window is empty), `proxy.rs` (routes, streaming passthrough, at most 2 retries on a connect error or a 503 before any body byte), `snapshot.rs` and `diagnosis.rs` (the balancer's stats view and its causes; the union leaves `drafter` `None`), `metrics.rs`. A proxied response with a declared `content-length` finishes its tracker by counting bytes, because hyper does not poll past it. `ModelStats::drafter` (`DrafterStats`: source label, `draft_tokens`, windowed `acceptance_ratio` from `LocalModel::draft_stats` samples) is what the penalty reads.
- **TUI** (`tui/`): follows `/cuca/v1/stats/stream` on a tokio task and draws on a blocking thread; tests draw it on `TestBackend`.

## Code Conventions & Common Patterns

Follow Rust defaults plus the conventions below:

- **Naming**: snake_case functions/variables, CamelCase types (`CucaClient`, `CucaPlugin`, `UnifiedRequest`, `MessageContentBlock`); plugin names are `&'static str` (e.g. `"opentelemetry-observability"`).
- **Error handling**: `CucaError` + `PluginError`; plugins return `Result<(), PluginError>`, client methods `Result<AgentResponseStream, CucaError>`. Avoid `unwrap`/`panic` in library code.
- **Async:** provider and async plugins use Tokio; the public stream contract is `futures_core::Stream` and yields `Result<MessageContentBlock, CucaError>`.
- **Feature gating:** `default = []`; `lib.rs` requires at least one `provider-*` feature. Provider, plugin, and service code MUST be `#[cfg(feature = "…")]`-gated, and each non-core dependency MUST be enabled only by its owning feature via `dep:`. Cross-tier feature and code edges additionally obey *Plugins and services* below.
- **Dependency injection**: providers via builder (`CucaClient::builder().with_provider(…).register_plugin(Arc<dyn CucaPlugin>)`); plugins as `Arc<dyn CucaPlugin>` (Send + Sync).
- **State management**: session state is append-only trajectory logs with fork support (`SessionStorePlugin`); no global mutable state.
- **Memory**: state that grows with traffic is capped, evicting or offloading at the bound; see *Memory discipline* below.
- **Data modeling**: `#[derive(Debug, Clone, serde::Serialize, serde::Deserialize)]` on all wire types.
- **Configuration is data**: no environment variable configures the crate. The library takes Rust structs (`LocalModelConfig`, `ServerConfig`, `BalancerConfig`); the `cuca` binary and the tests read one KDL file through `cuca::config` (`config-kdl`), and the struct field names are the KDL keys (a configuration type implements `Deserialize` with `deny_unknown_fields`, so a mistyped key is an error naming it). Two places read the environment: the `${VAR}` and `${VAR:-default}` placeholder lookup in `src/config/kdl.rs`, which runs after the file's `variables { }` block and only for names the file writes, and the platform cache directory in `src/provider/local/download.rs`. A new setting is a struct field, never an environment variable or a compact string grammar.

### Plugins and services (no cycles)

Core, plugins and services form a DAG at three levels: Cargo features, `#[cfg]`/import edges, and runtime coupling. Cargo rejects feature cycles; the code and runtime levels are on contributors.

**Tiers.** Core (`types`, `request`, `error`, `sse`, `session`, `plugin`, `client`, `provider`, `export`, `canonical`, `tokenize`, `cost_otel`) sits below every plugin and every service. The plugin tier is flat: `memory`, `session-log`, `mcp`, `sandbox`, `guardrails`, `subagent`, `hitl`, `web-search`, `skills`, `telemetry`, `cost`, and `redaction` depend on core only, and no plugin depends on another plugin. Services depend on core and on the plugin features they declare: `entity-extraction → memory` (hard, `service-entity-extraction = ["plugin-memory"]`), `replay → session-log` (hard, `service-replay = ["plugin-session-log"]`), `vector-store → memory` (hard, `service-vector-store = ["plugin-memory", "dep:wide"]`), and `speculative → session-log` (documented-optional: `ModelOrchestrator::with_session_store` records `SessionEvent::ModelSwap`); `prompt-cache`, `rate-limit` and `scheduler` declare no plugin dependency at all.

- **Direction is one-way:** a plugin MUST NOT name a service in any form: no `use crate::services::<name>`, no `cfg(feature = "service-<name>")` (including inside `cfg(all(…))`), no runtime lookup. `src/plugins/` stays ignorant that any service exists. A service→service edge requires re-tiering the shared part downward first.
- **Declare every code edge:** any compile-time reference from a service to a plugin it uses REQUIRES `service-<name> = ["plugin-<other>", …]` in `Cargo.toml`; never rely on a peer being co-enabled by accident.
- **Coordinate in core, never downward:** core MAY `#[cfg]`-reference any plugin or service; neither MUST reach a peer through a core module to dodge the two rules above. Multi-capability workflows live in core: `CucaExport::from_live` in `src/export.rs`, and `OtelCostObserver` in `src/cost_otel.rs`, the cost-ledger-to-OpenTelemetry bridge gated `cfg(all(feature = "plugin-cost", feature = "plugin-telemetry"))`.
- **No runtime peer discovery:** plugins and services MUST NOT look each other up. `CucaClient::plugins()` is an inspection accessor, not a service locator: no name matching, no downcasting. Cross-tier data moves through a caller-injected `Arc<dyn Trait>` or an explicit application hand-off (`EntityExtractionReport.delta` → `MemoryPlugin::merge_graph`).
- **Optional cross-tier behavior is documented and loud:** behavior that exists only when a declared peer is co-enabled or a peer handle is attached MUST be named in the owning module's `//!` docs, listed in the tiers above, and degrade loudly: compile-gated out of existence (`ModelOrchestrator::with_session_store`) or an explicit error (`CucaExportError::Unsupported` for a compiled-out export section). Silently doing nothing is a defect.
- **No hidden hook-order dependence:** `on_request` hooks run in registration order over one shared `UnifiedRequest`; a plugin MUST NOT require a position relative to another plugin. Where order is observable, document it at the consuming site: memory's graph/warning injections change the digest `PromptCache::lookup` computes afterward.
- **Explicit-call services:** a service is driven by direct method calls rather than pipeline hooks and MUST NOT implement `CucaPlugin` (`PromptCache`, `EntityExtractor`, `SessionReplay`, `ModelOrchestrator`, `RateLimiter`, `InMemoryVectorStore`, `Dispatcher`), so registering one is a compile error instead of an inert no-op; its `//!` header names the real entry points and any mandatory hand-off.

**Checks.** Every plugin or service feature MUST build alone on one provider (`cargo check --all-targets --no-default-features --features provider-openai,plugin-<name>` or `…,service-<name>`); CI runs that matrix across two jobs, `plugin_solo` and `service_solo`, which is how undeclared and reverse code edges are caught: `--all-features` cannot catch them. CI also greps every plugin directory for `service-` feature names, `crate::services` paths, and the `plugins::` paths the five moved modules left behind, since a `cfg(all(…))` reverse edge compiles in both the solo and all-features builds.

### Memory discipline (bounded by default)

Memory size is a first-order concern: every structure that grows with traffic ships bounded, with a stated policy at the bound.

- **Compact structures first.** Keep stream bytes in one reusable `BytesMut` scanned with `memchr` (`SseStreamParser`); pre-size known growth (`MemoryGraph::with_capacity`/`reserve`) instead of reallocating.
- **Cap every growable collection.** A new cache, log, buffer, or map that outlives one request REQUIRES a validated bound at construction, in the mold of `PromptCacheConfig::new` (rejects zero capacity), `MemoryConfig` (`max_messages`/`max_tokens`/`max_fraction`), `GraphContextConfig` (`max_nodes`/`max_relationships`), and `SandboxConfig::max_memory_bytes`. An uncapped collection is a defect unless its docs state why growth is bounded elsewhere.
- **Evict or offload at the cap.** State the at-cap policy in the owning type's docs and reuse an existing shape: TTL plus deterministic LRU eviction (`PromptCache`, `lru_order`), the ordered `CompactionStrategy` pipeline (`Offload` to a caller-supplied `VectorStore`, `Summarize`, `ClampOversizedMessages`, `SlidingWindow`), or append-only offload to disk (`SessionLogPlugin` with `FileBackend`). Unbounded growth is a defect; so is silent data loss.
- **Expose usage and warn near the cap.** A capped structure surfaces a cheap usage reading. Follow memory's seams: `ContextUsageObserver` receives a `ContextUsage` on every request (the reporting gauge), and `MemoryConfig::warn_fraction` injects a one-shot near-limit warning (idempotent via marker scan). Alerting and export belong on the caller-supplied OTel meter (`OpenTelemetryPlugin`); never install a global provider.
- **Re-verify bounds when touching hot paths.** A change to the SSE engine, compaction, a cache, or the graph MUST keep the owning module's `//!` allocation and bounds story accurate (`src/sse.rs` documents its per-frame allocations; `src/plugins/memory/graph.rs` documents its complexity envelope).
- **Local engine bounds**: the K/V block pool (`BatchingConfig::kv_tokens`, default twice `context_length` on the CPU, `context_length` plus at most 4,096 on a GPU), the running sequences (`max_sequences`, at most 64), the job queue (16) and the per-request event buffer (64), the tiered-expert byte budgets (`ExpertTiers::ram_bytes`, `device_bytes`) and the Engram row cache (`EngramCache::ram_bytes`, 1 MiB to 1 TiB, default 4 GiB, 48 bytes of bookkeeping counted per row; `reader_threads` 1 to 64, default 16) are fixed at load. At the bound the engine preempts the youngest sequence, evicts the least recently used unreferenced prefix block, evicts a cooler expert, or evicts the least recently used Engram row (a row evicted before its pass uses it is read again). `LocalModel::kv_cache_bytes`, `serving_stats`, `expert_tier_stats` and `engram_stats` read the usage; `docs/content/concepts/memory-discipline.md` explains the policy. The DeepSeek-V4.1 converter streams two buffers of at most 32 MiB of f32 (measured peak RSS about 220 MB).
- **Distributed-serving bounds**: at most `kv_export.max_exports` K/V leases (default 2) and 4 imports at once per model; each lease holds its blocks until the peer lets go or drops the connection, each import its blocks until the end frame or a failure. A stage worker keeps one token history per state slot, at most `max_sequences + 5` recurrent-state snapshots (the oldest is dropped; the coordinator releases the ones it drops) and the reply to its last call (one frame, replaced by the next call); it serves at most `MAX_STAGE_STREAMS` (8) frame streams per model, each with one thread, at most one frame in flight and a 300 s idle limit (a ninth upgrade is a 503). A coordinator holds, per remote stage, the tokens sent per slot and one connection; stage frames are at most 1 GiB (`MAX_STAGE_FRAME_BYTES`: one pass's rows, bounded by `max_step_tokens`).
- **Server bounds**: request bodies 32 MiB (layer-stage calls 1 GiB, `MAX_STAGE_BODY_BYTES` = `MAX_STAGE_FRAME_BYTES`); the latency window 60 s and 4,096 records (balancer: 1,024 per upstream); 300 one-second samples per model and for the machine; fixed atomic metrics labelled only by model, status code, upstream, GPU and remote-stage index; 64 stats streams; 32 events buffered per chat stream; 8 stage streams per worker model; 16 models per server, 256 upstreams per balancer; one stats snapshot per upstream. A structure that grows with traffic needs a bound and its at-cap policy documented in the module `//!`; `docs/content/concepts/memory-discipline.md` lists them.
